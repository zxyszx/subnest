# v0.3.36

## NewSzxcn shared inboxes

- Add a standalone Shared Inboxes admin page for configuring the API endpoint and read-only token, with mailbox and grant state restored after refresh.
- Sort mailboxes A-Z and support partial account search plus all, shared, and unshared filters. Each mailbox now has a focused flow to enable, manage, copy, preview, reset, or close sharing.
- Support rolling visibility windows of 30 minutes, 1 hour, 6 hours, 1 day, and 7 days with selectable mail folders.
- Add revocable SubNest short links without exposing the NewSzxcn API token, original share token, or upstream API address to browsers.
- Support read-only mailbox, folder, message, body, and attachment proxying in both Docker and Cloudflare Worker runtimes.

## Family sharing and visitor experience

- Allow family-sharing login fields to search NewSzxcn mailboxes. Managed sharing controls appear only for exact upstream mailbox matches, while ordinary email addresses keep a manually editable inbox URL.
- Allow matched mailboxes to enable a default 30-minute read-only share and expose copy/manage actions from account details.
- Redesign the visitor inbox with desktop list/detail panes, mobile list/detail navigation, attachment access, and clear revoked, expired, or invalid states.
- Render message HTML in an isolated sandbox that blocks scripts, forms, remote resources, and referrer leakage.

## Security and consistency

- Restrict the NewSzxcn API endpoint to `https://mail.newszxcn.com`, rejecting ports, credentials, query strings, and fragments to reduce SSRF exposure.
- Require a currently active authorization for every shared read; resetting or closing a share invalidates the previous short link immediately.
- Use the same allowlisted visibility windows across the UI, shared schema, Docker backend, and Worker.
- Fix shared-inbox response decoding and Docker route parameter syntax, and remove obsolete runtime parity exceptions.
