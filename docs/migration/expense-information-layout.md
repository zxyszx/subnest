# 费用信息页面：原版功能与业务映射

依据：用户提供的五张截图，以及本地原版 readable/assets/index-u_lcCyvf.js 的 traffic 统计文案。保留原版布局、主题、图表类型与模块顺序。

页面由仪表盘及三个明细导航组成，共四个标签。顶部“流量信息”改名“费用信息”。页内“用户、节点、服务器”分别改名“车友、合租、订阅服务”。费用信息为只读展示，新增、修改、续费、分配车位、收款进入顶部管理栏目。

## 共同功能

- 保留标签切换及数量徽标，今天／本周／本月范围切换。
- 列表保留搜索、筛选、排序、逐行查看明细；不在统计页提供编辑表单。
- 时间范围只作用于当期费用和收支统计；车位占用、有效状态为当前快照，7 天到期和续费日历为未来窗口。
- 车友用稳定 ID 识别；一位车友可关联多辆车，一辆车包含多个车位，订阅服务可关联合租车辆。
- 金额区分币种，未取得汇率时不得直接相加。实际付款与周期折算成本分别标注；不把月均成本当作已支付费用。
- 加载、请求失败、空数据分别显示；缺失记录不补造为零或“一切正常”。

## 仪表盘

第一排保持六张卡片：

| 原内容 | 费用信息内容 |
| --- | --- |
| 本月已用、统计服务器数量、迷你曲线 | 本月已付费用、计入订阅数、每日付款曲线 |
| 实时网速、上传下载、峰值、曲线 | 本月已收／已付及收支曲线 |
| 在线、连接数、IP 数 | 在车车友数、车辆数、已用车位数 |
| 服务器在线／总数、离线提示 | 有效订阅／总数、到期提示 |
| 有限额服务器配额、已用百分比 | 车位占用率、已用／总车位 |
| 用户状态、超额、总用户 | 待付款车友数、待收金额、车友总数 |

第二排：左侧保留近 30 天柱状图与 7 日均线，展示每日已付费用；右侧保留双线图，展示收入与支出。

第三排：用户用量排行→车友付款排行；节点用量排行→合租收入排行；流量去向→订阅费用分布环形图。

第四排（不可遗漏）：
- 需要处理：按严重程度展示逾期未收、已到期未续、7 天内到期订阅／车位；每项链接到对应顶部管理页面。已完成事项随数据更新消失。
- 服务器状态→服务状态：按订阅展示有效、即将到期、已到期、暂停等业务状态；保留原条形列表，进度条改为订阅周期进度。未接入可用性检测时，不显示“在线／故障”等监测结论。

## 用户→车友（图 2）

- 原五张卡：用户总数（多套餐人数）、今天活跃（当前在线）、人均用量、超额／接近额度、7 天内到期（已过期）。
- 新五张卡：车友总数（多车人数）、在车人数（当前有效关联）、人均当期应收、待付款／部分付款、7 天内车位到期（已到期）。
- 原三图：配额使用分布、套餐分布双环图、近 30 天每日活跃用户。
- 新三图：收款进度分布、上车服务分布（内圈人数／外圈应收）、近 30 天每日在车人数；历史在车人数需要历史记录，不用当前快照伪造。
- 全部车友表：车友、已上车辆、当期应收、实收／应收进度、待收金额、车位数、最近到期。
- 搜索姓名／车辆／联系方式；筛选全部、在车、待付款、部分付款、7 天内到期、已到期。点击车友展示其每个车位的车辆、费用、收款与期限。

## 节点→合租（图 3）

- 原四张卡：节点总数（服务器分布）、有流量／连接（闲置）、最忙节点、当前连接（协议数）。
- 新四张卡：车辆总数（订阅服务分布）、有车友的车辆（空车数）、当期收入最高车辆、已用车位（服务类型数）。
- 左侧流量地图→合租收入矩形树图：面积代表收入，按订阅服务分组。
- 右侧协议构成→服务构成双环图：内圈车辆数，外圈合租收入。
- 全部合租表：车辆、订阅服务、服务类型、当期实收、当期成本、已用／总车位、在车人数。
- 搜索车辆／订阅；筛选全部、有车友、空车、已暂停。点行展开该车各车友和车位明细。

## 服务器→订阅服务（图 4、图 5）

- 原五张卡：在线、总网速、本月已用、配额吃紧、当前连接（未来 30 天续费）。
- 新五张卡：有效／全部订阅、当期已付费用、当期合租实收、7 天内到期、未来 30 天续费金额。
- 左侧配额散点图→合租收支散点图：横轴周期进度，纵轴当期实收／当期应收，保留对角参考线；不适用合租的订阅不参与。
- 右侧保留未来 60 天续费时间轴：名称、距到期天数、日期、金额、预计节点；保留本月剩余待续费与下月预估。预测节点必须标注预计。
- 保留下方筛选：全部、已到期、7 天内到期、已暂停、30 天内到期；排序：默认、费用、到期、车位、名称。
- 保留订阅卡片网格：服务名称、距到期天数、状态、收支摘要、周期进度、续费周期／日期、关联车辆数、车友数、续费金额、当期已付。收入曲线只有真实历史记录时显示。
- 卡片点击只读详情，修改进入顶部订阅管理。

## 制作与接入边界

第一步输出本清单及独立的妙妙屋主题布局预览（expense-preview.html），预览数据明确标记为示例，不替换正式入口、不写业务数据。
第二步将已有真实订阅、合租、车位、收款和续费数据接入；缺少历史账本和稳定车友关系的项目需要补齐后才能形成真实统计。
